In production, Estudio Radio América runs inside a two-stage Docker container: Vite builds the static React bundle in the first stage, and a lightweight `nginx:stable-alpine` image serves it in the second. Nginx handles three responsibilities: serving the SPA, proxying API requests to the Node.js backend, and streaming uploaded video files directly from the backend without buffering them into memory.

## Full nginx.conf

```nginx nginx.conf
server {
  listen 8084;
  server_name _;
  client_max_body_size 0; # 0 = Sin límite de peso para subir videos

  location / {
    root   /usr/share/nginx/html;
    index  index.html index.htm;
    try_files $uri $uri/ /index.html;
  }

  # Redirigir peticiones API al backend de Node.js
  location /api/ {
    proxy_pass http://127.0.0.1:3005;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    
    # Transmisión directa: apagar el búfer para que el video Base64 fluya directo a Node.js
    proxy_request_buffering off;
    proxy_http_version 1.1;
    proxy_set_header Connection "";

    # Aumentar los tiempos de espera para peticiones largas (24 horas)
    proxy_connect_timeout 86400s;
    proxy_send_timeout 86400s;
    proxy_read_timeout 86400s;
  }

  # Servir los videos subidos directamente
  location /uploads/ {
    proxy_pass http://127.0.0.1:3005;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    
    # Optimización vital para streaming de video: evita que Nginx descargue todo el video en RAM antes de enviarlo
    proxy_buffering off;
    proxy_cache off;
  }
}
```

## How each location block works

### Static SPA serving (`location /`)

The root location serves the compiled React app from `/usr/share/nginx/html` — the directory where the Dockerfile copies the `dist/` output. The `try_files` directive is the key to SPA routing:

```nginx
try_files $uri $uri/ /index.html;
```

Nginx first looks for a file matching the requested path, then a directory with an `index.html`, and finally falls back to `/index.html`. This fallback ensures that client-side routes (e.g. `/programs/123`) return the React app rather than a 404.

### API reverse proxy (`location /api/`)

All requests whose path starts with `/api/` are forwarded to the Node.js backend running on `http://127.0.0.1:3005`. This is how `VITE_API_URL` defaults to `/api` in production — the relative path is resolved by Nginx on the same host, eliminating the need for CORS configuration.

Key directives:

| Directive | Value | Reason |
|---|---|---|
| `proxy_pass` | `http://127.0.0.1:3005` | Forwards to the Node.js backend on port 3005 |
| `proxy_request_buffering` | `off` | Streams Base64-encoded video directly to Node.js without loading it into Nginx memory |
| `proxy_http_version` | `1.1` | Required for keepalive and chunked transfer encoding |
| `proxy_connect_timeout` | `86400s` | Allows up to 24 hours for large file uploads |
| `proxy_send_timeout` | `86400s` | Keeps the upstream connection open for slow uploads |
| `proxy_read_timeout` | `86400s` | Waits up to 24 hours for the backend response |

<Warning>
  The 24-hour timeouts exist to support large video uploads. If your deployment does not
  handle large uploads, you can reduce these values (e.g. `300s`) to free up Nginx worker
  connections sooner.
</Warning>

### Video streaming (`location /uploads/`)

Uploaded videos are also proxied from the Node.js backend. `proxy_buffering off` and `proxy_cache off` prevent Nginx from downloading an entire video into RAM before starting to send it to the client — essential for streaming large files efficiently.

## File upload size

```nginx
client_max_body_size 0;
```

Setting `client_max_body_size` to `0` removes all size restrictions on incoming request bodies. This allows arbitrarily large video files to be uploaded through the `/api/` proxy.

<Note>
  If you receive HTTP 413 (Request Entity Too Large) errors, the `client_max_body_size`
  directive in your active Nginx configuration may not be set to `0`. Verify that
  `nginx.conf` is being loaded from `/etc/nginx/conf.d/default.conf` and that no
  conflicting value exists in `/etc/nginx/nginx.conf`.
</Note>

## Docker integration

The Dockerfile installs this configuration into the Nginx image during the production stage:

```dockerfile Dockerfile
FROM nginx:stable-alpine

COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 80
```

<Info>
  The container exposes port 80 even though `nginx.conf` listens on port 8084. Map the
  host port you want to the container port that Nginx actually listens on when running
  `docker run`. For example: `docker run -p 80:8084 estudio-radio-america`.
</Info>

## Relationship to VITE_API_URL

In production, `VITE_API_URL` defaults to `/api` (see `src/VideoContext.tsx`). Because the React bundle is served by Nginx, any fetch to `/api/videos` is a same-origin request that Nginx intercepts and forwards to `http://127.0.0.1:3005`. You only need to set `VITE_API_URL` explicitly if:

- The Node.js backend runs on a **different host** from the Nginx container.
- You want to use a **CDN or load balancer** in front of the backend.
- You are running the **development Vite server** without Docker.
